# 🧪 QA & Tester Guide

This document outlines the testing protocols for verifying Android builds across Staging, UAT, and Production candidates.

## 📥 1. Installing Test Builds

1. Navigate to the **[Releases Dashboard](/releases)**.
2. Select your designated environment (**Staging** or **UAT**).
3. Tap **Download APK** or scan the **QR Code** with your test device.
4. If prompted on Android, allow *“Install unknown apps”* from your browser/scanner.

---

## 🔍 2. Capturing Android Logs (ADB)

When encountering a crash, freeze, or ANR, capture the logcat using ADB:

```bash
# Clear old logs
adb logcat -c

# Stream logs filtered by app package
adb logcat | grep -i "com.james.app"

# Export full crash stacktrace to file
adb logcat -d > crash_log.txt
```

---

## 📝 3. Reporting Issues & Feedback

When filing a bug via the **Feedback Modal** on `/releases`:

1. **Build Version**: Ensure it matches the build under test (e.g. `v2.4.0-beta.2`).
2. **Device Model**: Include device name and Android OS version (e.g. *Pixel 8 Pro, Android 15*).
3. **Severity Classification**:
   - `Low`: Cosmetic layout alignment, copy mismatch.
   - `Medium`: Feature glitch with existing workaround.
   - `High`: Core business flow broken (e.g. checkout, login).
   - `Critical`: App crash, freeze, data loss.
4. **Reproduction Steps**: Detail step 1, step 2, expected vs actual behavior.
